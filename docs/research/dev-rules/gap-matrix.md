# Development Rules Gap Matrix

This matrix synthesises 1,339 development rules collected across 114 software projects into 42 distinct rule classes. It evaluates the current rule coverage of Praetor, the repository governance engine in cordanaLLM/praetor, against each class based on repository checks, tools, and workflows.

Coverage at source revision `247ae99da`, checked 2026-11-03: **19 covered, 19 partial, 3 gap, 1 not applicable**. Every coverage citation below names an existing repository file and its check or configuration key. Source inspection establishes wiring and scope; this correction round did not execute those gates or query the forge. Proposed checks and costs are design suggestions and estimates, not implemented or measured results.

Gaps and partials are ranked by defects caught before push per unit of cost: frequency across studied projects, execution latency, and applicability to Praetor's stack (Go, Python, JavaScript/TypeScript, Shell, YAML, Markdown).

## Top Gaps to Build First

These five candidate improvements retain the initial prioritisation by expected defect-detection density before push. Execution costs have not been benchmarked. Each item specifies a proposed negative fixture; none was implemented or executed in this documentation correction round.

### 1. Spelling and Typos Gate (`typos`)

- **Status**: Gap.
- **Stage**: `pre-commit` (Lefthook) and `CI` (`.github/workflows/ci.yml`).
- **Proposed check**: Run `typos --config .typos.toml` over staged files.
- **Planted case**: Add a Markdown file or Go comment containing `occured` or `seperate`. The check must exit with non-zero status and identify the exact file, line, and typo.

### 2. Coordinated Vulnerability Disclosure (`SECURITY.md`)

- **Status**: Gap.
- **Stage**: Proposed `pre-push` and `CI` via a new check wired through `cmd/standardsctl/audit.go`.
- **Proposed check**: Add root `SECURITY.md` defining private vulnerability reporting and verify its presence and contact section in `praetorctl audit`.
- **Planted case**: Remove `SECURITY.md` or clear its reporting contact. `praetorctl audit` must fail with `[FAIL] SECURITY.md: missing vulnerability disclosure contact`.

### 3. Maximum Line-Length Limit (`lll`)

- **Status**: Partial; existing checks cover hooks and registered assets.
- **Stage**: `pre-commit` (Lefthook) and `CI`.
- **Proposed check**: Extend line-length validation beyond the scope in `scripts/test_emitted_hook_lint.py`; add Go checking in `.golangci.yml` and update `lint_commands` in `.config/lefthook/scripts/checks.py`.
- **Planted case**: Add a Go statement spanning 135 characters without line breaks. `golangci-lint run` must exit 1 citing `line is 135 characters; max is 120`.

### 4. Commit Message Body 72-Column Wrap

- **Status**: Partial.
- **Stage**: `commit-msg` hook via `praetorctl forge check-message`.
- **Proposed check**: Extend commit-message validation in `internal/forge/commit_message.go` to reject prose lines longer than 72 columns and require a rationale.
- **Planted case**: Create a commit with an unwrapped 85-character body line. `praetorctl forge check-message` must exit 1 with `commit body line exceeds 72 columns`.

### 5. Mandatory Changelog Fragment on Non-Doc Changes

- **Status**: Partial.
- **Stage**: Proposed `pre-push` in `.config/lefthook/scripts/hooks.py` and `CI`, reusing `internal/cifilter/filter.go`.
- **Proposed check**: Require at least one new YAML file in `changelog.d/` whenever a pull request diff touches code under `cmd/` or `internal/`.
- **Planted case**: Commit a change to `cmd/standardsctl/main.go` without creating a file under `changelog.d/`. The proposed fragment check in `.config/lefthook/scripts/hooks.py`, `pre_push`, must abort with `missing changelog fragment for code change`.
