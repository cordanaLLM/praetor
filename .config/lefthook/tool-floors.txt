# The linters the hook policy runs on staged and pushed files (scripts/checks.py
# lint_commands) and the version floor each is held to. One requirement per
# line, in the shape .config/semgrep/requirements.txt and
# .config/hook-lint/requirements.in use, with >= where those pin with ==.
# scripts/toolchain.py reads this file: before a linter runs, the hook reads its
# --version and fails with the floor below when the tool is missing, states no
# version or is older. A linter is probed only when a file of its type is staged
# or pushed.
#
# A floor is the oldest version this tree's verdict is known to hold with, not
# a pin: a newer release passes. A floor needs a source in this repository, and
# each one names it. Raise one by hand, together with its source. A linter on a
# line of its own, without >=, has no such source: it must be installed, and
# any version of it is accepted.

# .github/actionlint.yaml: v1.7.12 rejects the ubuntu-26.04 runner label, which
# is why that file declares it (also internal/adopt/actionlint.go, #593).
actionlint>=1.7.12

# No floor. No workflow, container image or configuration file here installs
# hadolint or names a version of it, so there is nothing to derive one from; a
# version picked from one workstation would refuse contributors on another
# without evidence that the verdict on the root Dockerfile differs.
hadolint

# .github/workflows/portability.yml: SHELLCHECK_VERSION, the release every
# Platform Neutrality leg installs; the ubuntu-26.04 image ships the same one.
shellcheck>=0.11.0

# .config/hook-lint/requirements.in: the yamllint pin the hash-locked
# requirements.txt carries, which the Platform Neutrality legs install.
yamllint>=1.38.0
